# 超级音乐 App · 产品设计与实施文档

> 产品代号：**聆境 · Lingjing**（聆听之境）　备选名：回声 Echo / 拾音 Shinyl / 沐声
> 一句话定位：**一个零广告、多源聚合、沉浸式听歌的音乐播放器 —— 把全网音乐装进一个安静好看的壳里**
> 文档版本：v1.0 ｜ 2026-10-14 ｜ 状态：待确认

---

## 1. 项目背景与目标

### 1.1 为什么要做

通过对 7 个开源音乐项目与 8 款主流商业 App 的调研（详见第 2 章），发现当前音乐产品存在一个结构性矛盾：

- **商业 App**：版权全、算法强，但广告泛滥、会员墙高、界面臃肿、社交功能喧宾夺主 —— 用户只想安静听首歌。
- **开源播放器**：干净无广告、能聚合多源，但 UI 粗糙、体验断裂、无推荐、无多端同步、音源不稳。

**聆境要做的**：取两者之长 —— 开源产品的干净与自由 + 商业 App 的精致体验与算法，砍掉两者之糟粕（广告、社交、臃肿）。

### 1.2 产品目标

| 目标 | 衡量标准 |
|---|---|
| 零打扰 | 全程无任何广告、弹窗、开屏、推广位 |
| 全网曲库 | 单个搜索框聚合 ≥ 4 个音源，失效自动换源成功率 ≥ 90% |
| 沉浸体验 | 播放页达到 Apple Music 级歌词/取色/动效水准 |
| 多端一致 | PC（Electron）与 H5 同一套代码，体验一致 |
| 完全免费 | 全部基于开源库与免费接口，不接入任何付费服务 |

### 1.3 明确不做的事（减法清单）

- ❌ 社交：无评论、无动态、无私信、无粉丝
- ❌ 广告与商业化：无开屏、无信息流推广、无会员体系
- ❌ K 歌、直播、播客、有声书（保持"纯听歌"的纯粹性）
- ❌ 复杂多级页面：任何功能 ≤ 2 次点击可达

## 2. 竞品调研分析

### 2.1 开源项目盘点

| 项目 | 定位 | 值得借鉴 | 主要不足 |
|---|---|---|---|
| **Listen1** | 最早的聚合播放器（浏览器插件+桌面） | 聚合 7 大平台搜索；跨平台歌单；V2.9 自动切换失效播放源 | UI 陈旧、无推荐、无歌词翻译、迭代放缓 |
| **YesPlayMusic** | 高颜值网易云第三方（Vue） | 毛玻璃 UI、深浅主题、逐句歌词、私人 FM、去社交化的克制 | 仅单源；已进入维护模式；VIP 歌需外挂音源 |
| **Splayer** | Vue3+TS 简约网易云客户端 | 逐字歌词、音乐频谱、动态背景、自定义主题色、Web+客户端双形态（技术栈与我们最接近） | 不做移动端适配；单源 |
| **HyPlayer** | 功能最全的网易云第三方（C#） | 功能还原度高、SMTC 系统媒体控制 | 单源、仅 Windows、无 Web |
| **MusicFree / 洛雪音乐** | 插件化播放器 | **音源与壳解耦**：本体零音源，搜索/播放全靠插件市场，音源可热更新 | 音源质量参差；依赖第三方维护 |
| **FeelUOwn** | 插件化聚合播放器（Python） | 插件体系、多音质自动 fallback、架构清晰、可接 LLM | Linux 生态为主、UI 工程化低 |
| **musicn** | 命令行下载工具 | 极轻、可脚本化、Docker 部署 | 无 UI，仅适合"下载补库" |

**常用免费音源/API 现状**：GD 音乐台（多平台聚合、双语歌词）、六音音源（洛雪生态，多平台无损）、MusicFree 插件 hub、Unblocked-API（灰色歌曲替换）等。
**共性风险**：非官方接口，存在限频（如六音 3 秒 5 次封 IP）、随时失效 —— *这决定了我们的音源层必须设计「多源冗余 + 自动 fallback + 请求限流 + 缓存」*。

### 2.2 主流商业 App 优缺点

| App | 核心优点 | 用户真实痛点 |
|---|---|---|
| **网易云音乐** | 歌单生态与 UGC、评论区氛围、每日推荐/私人 FM、年度报告 | 版权日渐稀少；切后台回来强制开屏广告；界面臃肿功能定位模糊；"小众歌突然设 VIP"；自动续费投诉集中 |

| **酷狗/酷我** | 音质选项多、K 歌、蝰蛇音效 | 广告重灾区（借贷广告、"刷视频解锁红包"）；取消自动续费路径复杂；SVip 也不能完全去广告 |
| **汽水音乐** | 抖音算法推荐流、全屏沉浸上下滑切歌、极简 | 经典曲库薄；广告中断频繁；搜索/整理能力弱，不适合深度乐迷 |

| **Tidal** | 24bit/192kHz、Dolby Atmos | 贵、界面不直观、国内不可用 |

## 3. 产品定位与核心体验原则

### 3.1 设计三原则

1. **安静（Calm）**：界面是音乐的前奏，不是主角。留白、低饱和、无噪音。
2. **沉浸（Immersive）**：播放页即舞台 —— 动态取色背景 + 逐字歌词 + 流体动效。
3. **顺手（Fluent）**：所有高频操作 1 次点击；全局都有迷你播放条；键盘快捷键全支持。

### 3.2 目标用户

- 被广告与会员墙劝退、有一定动手能力的音乐爱好者
- 追求审美与氛围感的"视觉系"听歌人群
- 需求场景：通勤（H5）、工作学习（PC 后台听）、深夜沉浸（播放页）

### 4.1 功能模块总览

```
聆境 Lingjing
├── ① 聚合引擎（核心壁垒）
│   ├── 音源插件层（netease / kuwo / gdmusic / bilibili ...可插拔）
│   ├── 聚合搜索（并发检索、去重合并、按源筛选）
│   ├── 智能换源（健康度探测 → 失败 fallback → 请求限流 → URL 缓存）
│   └── 跨平台歌单导入（输入歌单 ID/链接一键迁移）
├── ② 播放内核

│   ├── Web Audio 频谱可视化 + MediaSession 系统媒体控制
│   ├── 播放模式（列表/单曲/随机）、音量淡入淡出、gapless

├── ③ 发现与推荐
│   ├── 每日推荐 30 首（本地行为数据 + 可调"熟悉/探索"配比）

│   ├── 流派/情绪电台（清晨、深夜、专注、通勤……）
│   └── 新歌速递
├── ④ 音乐库（我的）
│   ├── 我喜欢、最近播放、本地下载、云盘缓存
│   ├── 歌单管理（创建/编辑/排序/封面自动取色）
│   └── 本地文件与在线混播
├── ⑤ 歌词系统
│   ├── 逐字/逐句卡拉OK滚动、中英双语、翻译开关
│   └── 播放页沉浸大字排版 + 独立歌词页
└── ⑥ 工具
    ├── 睡眠定时器、均衡器（预设+自定义）

```

### 4.2 核心功能详细设计

#### ① 聚合引擎（本项目的技术壁垒）

- **架构**：音源适配器接口 `IMusicProvider { search / getSongUrl / getLyric / getAlbum }`，每个源一个插件文件，新增源零侵入。
- **搜索**：并发请求多源 → 按歌名+歌手模糊去重合并 → 展示"可用音源数"角标 → 支持按源筛选。
- **换源策略**：播放前探测首选源 URL 可用性（HEAD 请求 1.5s 超时）→ 失败按「健康度评分」自动切换下一源 → 全局请求队列限流（单源 ≤ 2 QPS）→ 歌曲直链缓存（有效期至 URL 失效前）。
- **导入**：粘贴网易云/QQ 音乐歌单分享链接 → 解析 ID 列表 → 逐首在多源中模糊匹配 → 生成聚合歌单（匹配失败的标记"待确认"）。

#### ② 沉浸播放页（本项目的体验壁垒）

- 打开方式：迷你播放条上滑 / 点击封面，带 **视差缩放转场**（封面从小图放大为背景）。
- 背景：从专辑封面实时提取主色，生成**流体渐变动态背景**（借鉴 Apple Music），暗色处理保证歌词可读。
- 歌词：逐字卡拉OK渲染（当前字渐变填充）+ 双语对照 + 拖动进度预览。
- 底部操作：喜欢（红心呼吸动效）、下载、音质切换、队列、更多。全部单手可达（H5）。

#### ③ 每日推荐

- 数据：本地播放/收藏/跳过记录构建画像（初始用流派偏好向导冷启动）。
- 配比：默认 70% 基于"喜欢"的相似推荐 + 30% 探索新流派，用户可滑杆调节。
- 仪式感：每日 0 点更新，封面卡片式呈现（借鉴网易云"每日推荐"仪式感 + Spotify 流派过滤）。

## 6. 交互设计细则

### 6.1 全局

- **迷你播放条**：常驻但不打扰 —— PC 悬浮右下（毛玻璃），H5 贴底（安全区适配）。进度以细线呈现，hover/长按展开控制。
- **转场**：页面间 200-300ms 淡入淡出 + 8px 位移；播放页用封面视差放大转场（450ms，spring 曲线）。
- **手势（H5）**：播放页下滑关闭、左右滑切歌、列表左滑显示"加入歌单"。
- **键盘（PC）**：Space 播放暂停、←→ 快进退、↑↓ 音量、L 喜欢、/ 聚焦搜索。

### 6.2 微交互打磨清单

| 场景 | 动效 |
|---|---|
| 点击喜欢 | 红心从点击点绽放 + 封面轻微弹跳（spring 300ms） |
| 切歌 | 封面交叉淡入 + 背景色 500ms 平滑过渡 |
| 逐字歌词 | 当前字渐变填充 80ms/字，行切换 translateY 350ms |
| 列表进入 | 曲目行 12ms 阶梯式 stagger 上浮 |
| 进度拖动 | 时间气泡跟随 + 封面暗化聚焦 |

## 7. 视觉设计规范（Design Tokens）

### 7.1 设计理念

**小清新 × 高级感 × 沉浸感** —— 白天像一本干净的乐评杂志，夜晚像一座私人音乐厅。

### 7.2 色彩体系

```
【亮色 · 主模式】（小清新）
  背景     #FAFAF7  暖米白（不用纯白，柔和不刺眼）
  表面     #FFFFFF  卡片
  主文字   #1A1D1F  墨黑
  次文字   #8A8F98  石墨灰
  主色     #5B8A72  苔原绿（低饱和、自然、清新）
  强调     #E8A87C  蜜杏橙（喜欢/高亮点缀）
  分割线   #ECECE7

【暗色 · 沉浸模式】（播放页/夜间）
  背景     动态取色生成（封面主色 → 暗化 85% 流体渐变）
  底色兜底 #101214  深墨
  文字     #F2F3F0 / #9BA1A6
```

### 7.3 字体与排版

- 中文：system-ui / PingFang SC / MiSans；数字：DIN 备选 tabular-nums
- 尺寸阶梯：12 / 13 / 15 / 17 / 22 / 28 / 34 / 44（播放页歌词 22px 起，当前行 28px 加粗）
- 行高：正文 1.6，歌词 1.5；字重只用 400/500/650 三档

### 7.4 形状与质感

- 圆角：卡片 16px / 按钮 12px / 封面 12px / 播放页大封面 20px（大圆角是"精致感"的关键）
- 阴影：极轻弥散 `0 8px 32px rgba(26,29,31,.06)`，禁止重投影
- 毛玻璃：侧边栏/迷你条/播放页控制区 `backdrop-filter: blur(24px) saturate(1.4)`
- 图标：线性 1.5px 圆头风格（类 Lucide），激活态描边加粗+主色

### 7.5 动效规范

- 时长：微交互 150-300ms / 转场 300-450ms / 背景过渡 500ms
- 曲线：常规 `cubic-bezier(.22,1,.36,1)`，弹性 `spring(stiffness 300, damping 26)`
- 原则：所有动效可被"减少动态"设置关闭（无障碍）

## 8. 技术方案

### 8.1 架构

```
┌─ 前端（一套代码，双形态）─────────────────────┐
│ Vue 3 + Vite + TypeScript + Pinia + Vue Router │
│ PC：Electron 壳（桌面歌词/SMTC/托盘）           │
│ H5：Vite PWA（离线缓存/添加到主屏）             │
└──────────────┬───────────────────────────────┘
               │ HTTP / WebSocket
┌─ 后端 ───────┴───────────────────────────────┐
│ NestJS + Prisma + SQLite                      │
│ 用户数据：歌单/收藏/播放记录/设置同步           │
│ 音源代理层：服务端统一请求（防 IP 封禁）        │
└───────────────────────────────────────────────┘
```

### 8.2 关键技术点

- **音源插件**：NestJS Provider 注册表 + 前端同名 adapter，新增源 = 新增一个类文件
- **限流**：`bottleneck` 每源令牌桶；**缓存**：歌曲 URL Redis/内存 TTL 缓存、封面 CDN 镜像缓存
- **频谱**：Web Audio `AnalyserNode` + Canvas 绘制（播放页背景随频谱呼吸）
- **媒体控制**：MediaSession API（H5）+ Electron SMTC（PC）
- **部署**：前端 Vercel（免费）、后端 Render free 层、数据库 SQLite 文件随 Render 持久卷
- **降级策略**：后端不可用时前端直连音源（本地限流），保证 H5 仍可用

### 8.3 合规与风险

- 定位**个人学习/自用工具**，不商业化、不分发音源破解内容
- 音源接口均为公开非官方接口，存在失效风险 → 多源冗余 + 插件热更新机制对冲
- 不存储任何音频文件于自有服务器，仅缓存临时播放直链
